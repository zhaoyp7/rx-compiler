# never 类型

never 类型通常写作 `!`，用于描述不会正常完成的表达式；这类表达式被称为*发散*。
它在内部使用；`!` 不是有效的源代码类型注解。

`return`、`break` 和 `continue` 表达式具有 never 类型：它们在出现的位置转移控制流，
而不是产生一个值。当一个[块表达式](../11-expressions/11.03-block-expr.md)的所有执行路径都通过
这些转移提前退出时，它同样具有 never 类型。

never 类型可以在受支持的[强制转换上下文](10.00-types.md#conversions-and-coercions)中
强制转换为任何期望的结果类型。没有期望类型时，never 结果不会约束其他结果的公共类型；
如果所有结果都是 never，则该公共类型为 never。这允许一个 if 分支提前返回，而另一个
分支产生值，包括引用或容器。单元类型 `()` 与 never 类型 `!` 是不同的：求值为 `()` 的
表达式正常完成，而 never 类型的表达式不会。

```rust,ignore
fn choose_or_return(flag: bool) -> i32 {
    let n: i32 = if flag { return 7; } else { 3 };
    n + 1
}
```

发散的函数体满足任何声明的返回类型，例如
`fn forever() -> i32 { loop {} }`。对该函数的调用具有其声明的类型 `i32`。
never 行为在每个函数体内部局部确定。

## 循环表达式

如果没有 `break` 表达式以某个 `loop` 表达式为目标，则该 `loop` 表达式具有 never 类型。
嵌套循环内部的 `break` 以该嵌套循环为目标，因此
`loop { loop { break; } }` 仍然具有 never 类型。

如果有任何 `break` 表达式以该循环为目标，则它们的值遵循
[公共结果规则](10.00-types.md#least-upper-bound-coercions)，在提供了循环的期望类型时使用
该期望类型；`break;` 提供 `()`。如果每个 break 操作数都具有 never 类型，
则该循环也具有 never 类型。break 表达式即使不可达也会参与类型推断：
`loop { if false { break 1i32; } }` 的类型是 `i32`。

这些规则适用于 `loop`。`while` 表达式的类型是 `()`，即使其条件始终为真。

## 不可达代码

不可达代码仍然需要通常的语义检查，包括名称解析、类型检查和位置可变性检查。
被明确归类为未定义行为的情形不需要诊断信息。

对于处于测试保证范围内的程序，生成的代码必须遵守控制流转移。`return` 退出当前函数，
`break` 退出其目标循环，`continue` 继续到下一次迭代。被这些转移绕过的代码不得执行。

不可达代码中的位置可变性违规在[测试保证](../01-undefined-behavior/01.00-undefined-behavior.md#test-guarantees)下表现出
未定义行为。这包括对不可变位置的普通赋值和复合赋值、对不可变位置的可变借用，以及
需要不可用的可变访问的方法或索引调整。该规则涵盖局部变量、结构体字段、索引元素和
解引用位置。这些违规不需要诊断信息。例如：

```rust,ignore
fn example() {
    let value = 1;
    let shared = &value;
    return;
    value = 2; // undefined behavior: immutable local assignment after return
    let borrowed = &mut *shared; // undefined behavior: mutable borrow after return
    *shared = 3; // undefined behavior: write through a shared reference after return
}
```

该排除专门适用于位置可变性。名称解析错误、类型不匹配错误，以及不是位置表达式的
赋值目标，即使在不可达代码中也仍然是必需的编译错误。

编译器实现不需要在其 AST 或 IR 中显式表示 never 类型，也不需要解决停机问题或证明终止。
