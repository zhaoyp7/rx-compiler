# 类型与类型推断

```grammar,types
Type -> TypeNoBounds

TypeNoBounds ->
      ParenthesizedType
    | TypePath
    | UnitType
    | ReferenceType
    | ArrayType

ParenthesizedType -> `(` Type `)`
```

## 支持的类型

| 类型 | 含义 |
| --- | --- |
| `i32`, `isize` | 不同的有符号 32 位整数 |
| `u32`, `usize` | 不同的无符号 32 位整数 |
| `bool` | 布尔值 |
| 具名结构体；在其声明或 impl 中的 `Self` | 名义的具名字段积类型 |
| `[T; N]` | 具有受限 `usize` 常量长度的固定数组 |
| `&T`, `&mut T`, `&'a T`, `&'a mut T` | 共享引用或可变引用 |
| `()` | 函数或控制流结果 |
| [`Box<T>`, `Vec<T>`](10.03-heap.md) | 拥有的堆对象或动态序列 |

发散表达式在内部使用 [never 类型](10.05-never.md)。

结构体类型是名义的。引用、数组、`Box` 和 `Vec` 是结构化的。四种整数类型保持彼此不同。数组长度按值比较，因此 `[i32; 4]` 与 `[i32; (4usize)]` 完全相同。两个引用类型完全相同，当且仅当它们所指的类型与可变性都匹配；生命周期实参不区分引用类型，并且必须满足[生命周期有效性保证](../01-undefined-behavior/01.00-undefined-behavior.md#lifetime-validity)。

## 类型推断

类型推断根据初始化表达式填补被省略的局部绑定类型。函数与项的签名是显式的。每个绑定只有一个固定类型；后续使用不会改变它。在 `Box` 和 `Vec` 构造函数调用中省略显式的具体类型实参是[未定义行为](../14-heap/14.00-heap.md#builtin-signatures)。在字段或方法查找之前，必须已知接收者的类型。

### 整数字面量

整数字面量按顺序使用以下受限的类型推断规则：

1. 后缀固定类型。
2. 没有后缀时，如果期望类型是 `i32`、`u32`、`isize` 或 `usize` 之一，则使用该期望类型。
3. 否则使用 `i32`。

期望类型来自[下文的情境与传播规则](#coercion-sites-and-expected-types)。没有这种期望时，另一个操作数、相邻的数组元素或分支，以及绑定的后续使用都不会选择该字面量的类型。一旦选定，整数类型不会隐式改变。

```rust,ignore
let n = 1;                   // i32: no expected type
let count: u32 = 1;          // u32: from the annotation
let sum: u32 = 1 + 2;        // undefined behavior: needs propagation through +
let neg: isize = -1;         // undefined behavior: needs propagation through unary -
let r: &u32 = &1;            // undefined behavior: needs propagation through &
let values: [u32; 2] = [1, 2]; // u32 elements; usize length
let bad: u32 = 1i32;         // compile error: a suffix fixes the type
let later: u32 = n;          // compile error: n is already i32
let mixed = 1 + 2u32;        // compile error: no expected type for 1
```

数组长度和索引的期望类型是 `usize`，因此 `[i32; 4]`、`[0; 4]` 和 `data[0]` 无需后缀即可有效。范围检查在类型选择之后进行：如果整数字面量的值超出所选类型的可表示范围，则表现出[未定义行为](../01-undefined-behavior/01.00-undefined-behavior.md#integer-literal-range)。字面量的大小绝不会导致选择不同的整数类型。

## 转换与强制转换

显式转换使用 `as`。强制转换是在下文列出的某个表达式位置上进行的自动调整。其组织方式遵循 [Rust 参考手册](https://doc.rust-lang.org/reference/type-coercions.html)，但仅包含 Rx 支持的类型与操作。

### 显式转换

整数到整数以及布尔到整数的转换需要 `as`。整数类型转换保留 32 位模式；`false` 变为 0，`true` 变为 1。这些是唯一受支持的[类型转换](../11-expressions/11.04-operator-expr.md#casts)。条件要求类型为 `bool` 的表达式；整数值不能用作条件，也不会被隐式转换。

### 强制转换位置与期望类型

**一对一强制转换（one-to-one coercion）** 将一个表达式与已知目标进行核对，该目标称为其*期望类型*。**最小上界（least upper bound，LUB）强制转换**为若干表达式寻找一个公共目标。这一区分遵循 [Rust 编译器开发指南](https://rustc-dev-guide.rust-lang.org/hir-typeck/coercions.html)。期望的整数类型可以在强制转换之前选择无后缀字面量的类型；强制转换本身并不转换整数。

以下位置具有已知的期望类型，并使用一对一强制转换：

| 表达式位置 | 期望类型 |
| --- | --- |
| 带注解的 `let` 初始化表达式 | 注解 |
| 常量初始化表达式 | 声明的常量类型，受限于受限的[常量形式](../12-const_eval/12.00-const_eval.md) |
| 赋值右操作数 | 目标位置 |
| 函数、方法或容器构造函数实参 | 声明的参数；方法接收者遵循[接收者调整](../11-expressions/11.10-method-call-expr.md#method-lookup) |
| 函数尾表达式或 `return` 操作数 | 声明的结果 |
| 结构体字段初始化表达式 | 声明的字段 |

期望类型会穿过圆括号传播，进入块尾表达式，传播到 `if` 表达式的两个结果分支，以及所有以某个 `loop` 为目标的 `break` 值表达式。期望的数组类型 `[T; N]` 将 `T` 提供给每个列出的或重复的元素，并要求长度为 `N`。这些结果表达式中的每一个都要针对该目标进行核对；除下文的传播排除情形外，核对失败即为编译错误。

传播只通过上文列出的形式重复进行。它不会穿过二元运算、一元运算或借用表达式（`&e` 和 `&mut e`），也不会回过头去处理先前的绑定初始化表达式。如果程序为了确定整数字面量的类型而需要穿过运算符或借用表达式进行类型传播，其行为是**未定义行为**，而不是触发必需的编译错误。

这里排除的是对传播的依赖，而不是运算符或借用本身。例如，`let n: i32 = 1 + 2;` 通过默认规则成立，而 `let r: &u32 = &1u32;` 成立是因为后缀固定了类型。由后缀或现有绑定固定下来的不兼容类型仍然是编译错误。调用实参仍然会获得其声明的期望类型，即使位于运算符或借用内部也是如此。

```rust,ignore
// Expected type u32 propagates into block tails, if branches, and loop breaks:
let x: u32 = { 1 };                            // valid: 1 receives expected type u32
let y: u32 = if true { 1 } else { 2 };         // valid: 1 and 2 receive expected type u32
let z: u32 = loop { break 42; };               // valid: 42 receives expected type u32

// But expected type does NOT penetrate operators or borrows:
let a: u32 = 1 + 2;                            // undefined behavior (requires propagation through +)
let b: &u32 = &1;                              // undefined behavior (requires propagation through &)
let c: &u32 = &1u32;                           // valid: suffix fixes the literal type
```

条件要求 `bool`，数组长度和索引的期望类型是 `usize`，而循环体以及没有 `else` 的 `if` 要求单元类型的结果。运算符遵循其[操作数规则](../11-expressions/11.04-operator-expr.md)。这些要求不会启用额外的转换。

### 强制转换类型

只支持以下调整：

| 源 | 目标 | 调整 |
| --- | --- | --- |
| `T` | `T` | 保持该类型；适用普通的复制/移动规则，但下文的可变引用重借用除外 |
| `&mut T` | `&T` | 通过共享引用借用同一个值 |
| `&S` 或 `&mut S` | `&T` | 沿内置解引用从 `S` 到达 `T` 位置，然后借用它 |
| `&mut S` | `&mut T` | 沿内置解引用从 `S` 到达可变 `T` 位置，然后可变地借用它 |
| Never | 任意目标 | 在该路径上不产生任何值 |

内置解引用步骤是 `&U` 到 `U`、`&mut U` 到 `U` 以及 `Box<U>` 到 `U`。这些步骤可以重复进行，直到目标的所指类型完全匹配。可变目标要求外层为 `&mut`，且路径上没有任何共享引用。该调整借用到达的值，而不移动其内容。`Vec` 没有内置解引用。

```rust,ignore
let mut boxed = Box::<i32>::new(1);
let r: &i32 = &boxed;           // &Box<i32> to &i32
let m: &mut i32 = &mut boxed;   // &mut Box<i32> to &mut i32
```

强制转换不会隐式借用拥有的值：`Box<T>` 不能强制转换为 `T` 或 `&T`；对于后者需要写 `&boxed`。它不会转换存储的数组或容器元素，不会改变内部引用的可变性，也不会产生切片。例如，`&mut &mut i32` 不能强制转换为 `&mut &i32`。数组*字面量元素*可以各自进行强制转换，因为它们是彼此独立的表达式位置。

### 可变引用重借用

> **注意**：由于我们保证生命周期有效，本项目不需要了解重借用。这里保留它仅仅是为了规范的完整性。

在强制转换位置，`&mut T` 可以再次作为 `&mut T` 被借用。这就是*重借用*：新借用结束后，原来的引用又可以重新使用。而未加注解的 `let` 绑定则会移动该引用：

```rust,ignore
let mut x = 1;
let p = &mut x;
{
    let q: &mut i32 = p; // reborrow
    *q = 2;
}
*p = 3;
let moved = p;           // move
*moved = 4;
```

移动之后，除非重新初始化，`p` 不能再次使用。将 `p` 作为实参传给 `&mut i32` 参数会以同样的方式重借用它。后续使用不会把移动变成重借用。

### 最小上界强制转换

当没有期望类型固定目标时，LUB 强制转换为以下情形寻找公共类型：

- 带 `else` 的 `if` 的结果分支。
- 数组字面量的元素。
- 以同一个 `loop` 为目标的所有 `break` 表达式的值。

有期望类型时，这些相同的表达式会使用一对一强制转换到那个固定目标。函数返回和函数尾表达式也共享一个固定目标：声明的结果类型。它们绝不会推断出不同的函数签名。

对于未知目标，首先独立确定每个结果的类型，对没有期望整数类型的无后缀整数使用 `i32`。当前 LUB 目标不是其他结果的期望类型。按源代码顺序考虑结果，并忽略可以适应任何目标的 never 结果。以第一个剩余结果的类型作为当前目标 `T`。对于类型为 `U` 的每个后续结果：

1. 如果 `U` 可以强制转换为 `T`，则保留 `T`。
2. 否则，如果 `T` 可以强制转换为 `U`，并且每个更早的结果都能调整到 `U`，则使用 `U` 作为新目标，并同样调整那些结果。
3. 如果不满足，则行为未定义（[未定义行为](../01-undefined-behavior/01.00-undefined-behavior.md#test-guarantees)）。不要求搜索第三种公共类型。

如果所有结果都是 never，则结果类型为 never。空数组遵循[零大小数据排除](../01-undefined-behavior/01.00-undefined-behavior.md#zero-sized-data)。裸 `break;` 提供 `()`；以嵌套循环为目标的 break 不参与其中。

下表的每一行都是一个独立的示例：

| 表达式 | 结果 |
| --- | --- |
| `let a = [&mut 1, &123];` | `[&i32; 2]`；第一个元素变为共享 |
| `let a = [&123, &mut 1];` | 类型相同；第二个元素变为共享 |
| `let a = [&mut 1u32, &123u32];` | `[&u32; 2]` |
| `let a = [&mut 1u32, &123];` | 未定义行为：`123` 没有期望类型，因此它是 `i32` |
| `let a: [&u32; 2] = [&mut 1, &123];` | 未定义行为：推断 `u32` 需要穿过两个借用进行传播 |
| `let a: [&u32; 2] = [&mut 1u32, &123u32];` | 有效：字面量已经是 `u32`；第一个引用强制转换为共享引用 |
| `let a = [&mut &1, &mut &mut 2];` | 未定义行为：内部引用的可变性不同 |
| `let a: [&mut &i32; 2] = [&mut &1, &mut &mut 2];` | 编译错误：第二个元素无法满足固定的期望类型 |

这些规则决定表达式的类型；它们不会改变求值顺序，也不改变单独的方法与运算符调整规则。

## 递归类型

按值包含的结构体或数组成环没有有限大小，属于编译错误。引用、`Box` 和 `Vec` 提供间接性，因此通过这些类型的递归结构体和相互递归结构体是受支持的。

```rust,ignore
struct Node {
    value: i32,
    children: Vec<Node>,
}
```

<details>
<summary>递归布局细节</summary>

`struct Infinite { child: Infinite }` 无效，因为子字段是内联的；内联数组也无法打破该循环。在另一个声明中于容器（例如 `Box` 或 `Vec`）内部引用一个无效的循环类型，并不会使该循环类型定义变得有效。

```rust,ignore
// Invalid: infinite size due to inline containment cycle
// struct BadNode { child: BadNode }
// struct BadArray { items: [BadArray; 1] }

// Valid: indirection breaks the layout cycle
struct GoodNode {
    child: Box<GoodNode>,
}
```

有限布局并不意味着可构造性。`struct Chain { next: Box<Chain> }` 具有有限布局，但由于 `Box` 不可为空，它没有终止值。这并不会使其声明无效。

实现可以只检查通过内联结构体和数组依赖形成的循环。容器 API、trait 能力以及回收分别在 [Box 和 Vec](../14-heap/14.00-heap.md) 中定义。

</details>
