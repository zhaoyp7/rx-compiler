# 名称和作用域

## 作用域规则

顶层函数、结构体、常量和固有关联项引入名称。参数和 `let` 语句引入局部绑定。字段属于其所在结构体的命名空间，并通过接收者的类型进行解析。

[Use 声明](../07-items/07.01-use-declarations.md)在 Rx 中不引入名称，既不参与名称解析也不参与冲突检查。导入的路径和别名可以在解析后丢弃；内置环境独立于这些声明。

顶层和关联项查找独立于声明顺序。局部绑定仅在其初始化器之后可见，直到其块结束，并受遮蔽影响。常量初始化器、数组长度和数组重复长度可以在[常量上下文规则](../12-const_eval/12.00-const_eval.md)下使用常量项路径，这些规则还要求常量依赖无环。

`self` 表示方法接收者。`Self` 表示正在声明的结构体或当前固有实现的目标类型，包括在其关联项内部。两者都不是普通的用户定义标识符，且 `Self` 不能用于在 `impl` 块之外声明的顶层函数中。

生命周期名称占用单独的命名空间，受[生命周期参数](../07-items/07.07-generics.md)和[生命周期有效性保证](../01-undefined-behavior/01.00-undefined-behavior.md#lifetime-validity)约束。

### 类型和值命名空间

类型和值使用单独的命名空间：

| 上下文 | 命名空间 |
| --- | --- |
| 类型位置中的结构体名称、原始类型、`Box`、`Vec` 或 `Self` | 类型 |
| 表达式中的函数、常量、局部绑定或 `self` | 值 |
| `Type::member` 的前缀 | 类型 |
| 结构体字段 | 该结构体的字段命名空间 |

具名字段结构体不是可调用的值构造函数；因此，结构体和函数可以共享同一名称而不发生冲突。

## 名称冲突

顶层名称在其命名空间内必须唯一。结构体内的字段和函数内的参数也必须唯一。一个结构体的所有固有实现共享单个关联值命名空间；定义重复的方法、关联函数或关联常量是编译错误，无论它们的签名如何，也不论它们是否跨不同的 `impl` 块声明。结构体字段和固有方法可以共享同一名称，因为它们位于不同的命名空间中。

连续的 `let` 绑定可以遮蔽先前的局部变量、参数和非受保护全局函数。查找解析到最近的外围绑定；如果该绑定不可调用，则调用是编译错误，而不是回退到外层被遮蔽的函数。`let` 绑定的初始化器表达式在引入新绑定之前的作用域中求值。

与可见的非限定常量冲突的 `let` 或普通参数，根据集中式的[常量名称冲突保证](../01-undefined-behavior/01.00-undefined-behavior.md#constant-name-collisions)，属于未定义行为。

## 受保护的内置名称

以下名称在各自的命名空间中受保护：

| 命名空间 | 受保护名称 |
| --- | --- |
| 类型 | `i32`, `u32`, `isize`, `usize`, `bool`, `Box`, `Vec`, `Copy`, `Clone`, `PartialEq`, `Eq` |
| 值 | `get_i32`, `print_i32`, `println_i32` |
| 派生入口 | `Copy`, `Clone`, `PartialEq`, `Eq` |

这些受保护名称仍然是有效的词法标识符。它们可以用在其他命名空间中，或作为字段和关联项名称（例如，名为 `Vec` 的字段是有效的）。由于固有实现只能为用户定义的结构体声明，因此不能向受保护的内置类型添加固有方法。

以下冲突根据[测试保证](../01-undefined-behavior/01.00-undefined-behavior.md#test-guarantees)属于未定义行为，不要求任何诊断或行为：

- 声明名为 `u32`、`isize`、`usize`、`bool`、`Box`、`Vec`、`Copy`、`Clone`、`PartialEq` 或 `Eq` 的结构体。
- 声明名为 `get_i32`、`print_i32` 或 `println_i32` 的局部绑定（`let` 或普通参数）。

在各自命名空间中对受保护内置项的其他重新声明是编译错误，包括定义名为 `i32` 的结构体，或声明具有受保护 I/O 名称的顶层函数或常量。
