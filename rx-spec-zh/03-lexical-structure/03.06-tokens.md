r[lex.token]
# 词法单元

r[lex.token.syntax]
```grammar,lexer
@root Token ->
      IDENTIFIER_OR_KEYWORD
    | INTEGER_LITERAL
    | LIFETIME_TOKEN
    | PUNCTUATION
```

词法单元是标识符或关键字、整数字面量、生命周期词法单元和标点。关键字（包括布尔字面量 `true` 和 `false`）与标识符共享词法字符模式，但它们的语法角色由关键字规则和 [LiteralExpression] 产生式确定。

词法分析在受下面数值和生命周期边界约束的前提下选择最长的词法单元。解析器可以根据[上下文标点](../04-grammar/04.00-grammar.md#contextual-punctuation)消费组合标点的前缀。

## 整数字面量

r[lex.token.literal.int.syntax]
```grammar,lexer
INTEGER_LITERAL ->
    ( DEC_LITERAL | BIN_LITERAL | OCT_LITERAL | HEX_LITERAL ) INTEGER_SUFFIX?

DEC_LITERAL -> DEC_DIGIT (DEC_DIGIT|`_`)*

BIN_LITERAL -> `0b` (BIN_DIGIT|`_`)* BIN_DIGIT (BIN_DIGIT|`_`)*

OCT_LITERAL -> `0o` (OCT_DIGIT|`_`)* OCT_DIGIT (OCT_DIGIT|`_`)*

HEX_LITERAL -> `0x` (HEX_DIGIT|`_`)* HEX_DIGIT (HEX_DIGIT|`_`)*

BIN_DIGIT -> [`0`-`1`]

OCT_DIGIT -> [`0`-`7`]

DEC_DIGIT -> [`0`-`9`]

HEX_DIGIT -> [`0`-`9` `a`-`f` `A`-`F`]
```

```grammar,lexer
INTEGER_SUFFIX -> `i32` | `u32` | `isize` | `usize`
```

整数字面量使用十进制数字或二进制、八进制、十六进制前缀，并可选择使用下划线分隔符。非十进制字面量在前缀之后必须至少包含一个数字。这四个整数后缀指定对应的整数类型。

| 形式 | 示例 |
| --- | --- |
| 十进制 | `123`, `1_234`, `123_i32` |
| 二进制 | `0b1010`, `0b____1`, `0b10_u32` |
| 八进制 | `0o77`, `0o7_usize` |
| 十六进制 | `0xff`, `0xAB_CD`, `0xff_isize` |

词法分析器使用最长匹配消费完整的数值词法单元。词法分析器不得通过将输入拆分为一个有效整数词法单元后跟尾随词法单元的方式，从无效后缀或无效进制数字中恢复；诸如 `123i32foo`、`123bad`、`0b102` 和 `0x` 这样的拼写必须作为无效词法单元被拒绝。所提供的 Rust 词法分析器可以保留通用后缀，并在语言子集边界处拒绝不支持的后缀。

没有词法单元长度或数值大小限制。编译器必须保留原始数字和后缀，而不要求字面量的大小适合宿主平台的整数类型。类型确定和范围有效性遵循[字面量表达式](../11-expressions/11.01-literal-expr.md#integer-typing-and-range)。

超出其确定类型范围的字面量是未定义行为；请参见[整数字面量范围保证](../01-undefined-behavior/01.00-undefined-behavior.md#integer-literal-range)。

前导负号（`-`）被词法分析为单独的运算符，而不是整数字面量的一部分。由于 `f`、`3` 和 `2` 是有效的十六进制数字，`0x01_f32` 被解析为单个十六进制整数字面量，其值为 `0x01f32` 且没有后缀，而不是作为浮点字面量。

## 生命周期

r[lex.token.life.syntax]
```grammar,lexer
LIFETIME_TOKEN -> `'` IDENTIFIER_OR_KEYWORD

LIFETIME_OR_LABEL -> `'` NON_KEYWORD_IDENTIFIER
```

生命周期词法单元由一个撇号紧跟其名称组成，中间没有空白或注释。词法分析器消费完整的名称。示例包括 `'a`、`'data`、`'static` 和 `'_`。生命周期词法单元后面不得跟闭合撇号；诸如 `'a'` 这样的拼写表示字符字面量，Rx 不支持字符字面量。

[LIFETIME_OR_LABEL] 为 [Lifetime] 提供普通具名生命周期。特殊拼写 `'static` 和 `'_` 在那里有各自的备选项。生命周期词法单元出现在引用类型、参数声明、路径参数和约束中。尽管词法分析器产生式 `LIFETIME_OR_LABEL` 匹配循环标签词法单元，Rx 控制流产生式（[循环](../11-expressions/11.12-loop-expr.md)）不支持带标签的循环或跳转。

## 标点

r[lex.token.punct.syntax]
```grammar,lexer
PUNCTUATION ->
      `=` | `<` | `<=` | `==` | `!=` | `>=` | `>`
    | `&&` | `||` | `!`
    | `+` | `-` | `*` | `/` | `%` | `^` | `&` | `|` | `<<` | `>>`
    | `+=` | `-=` | `*=` | `/=` | `%=` | `^=` | `&=` | `|=` | `<<=` | `>>=`
    | `.` | `,` | `;` | `:` | `::` | `->` | `#` | `_`
    | `{` | `}` | `[` | `]` | `(` | `)`
```

注释优先于 `/` 标点。组合运算符遵循最长词法单元规则；它们的上下文拆分在[解析器约定](../04-grammar/04.00-grammar.md#contextual-punctuation)中指定。

Rx 不支持浮点数；包含小数或指数部分的数值词法单元（例如 `1.0` 或 `1e5`）必须作为词法错误被拒绝，而不是拆分为整数和标点词法单元。分隔符（圆括号、方括号和花括号）必须始终成对出现。`#` 字符专门用于引入外部派生属性。
