# 后端

## 目标和工具链

唯一的目标是采用 ILP32 数据模型的小端 RISC-V RV32IM。外部 C 和 REIMU 接口使用基整数 [RISC-V ELF psABI](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/)，即定义分别编译的代码如何互操作的处理器专用应用二进制接口。内部调用约定由实现定义。

| 组件 | 所需配置 |
| --- | --- |
| Clang/LLVM | 版本 22 |
| 目标 | `riscv32-unknown-elf` |
| ISA 和 ABI | `-march=rv32im -mabi=ilp32` |
| REIMU | 待定 |
| 执行内存 | `--memory=256M` |
| 栈 | `--stack=1M` |

编译器发出 GNU 风格的文本汇编，既被 Clang 集成汇编器接受，也被固定的 REIMU 版本接受。Clang 汇编或 REIMU 解析、链接或执行期间的任何失败都构成契约违反。不得发出 Clang 接受但 REIMU 不支持的汇编语法。测试不要求特定的指令选择、栈帧形态、寄存器分配器、符号布局或汇编文本。

RISC-V 指令行为遵循课程固定的 RISC-V 非特权 ISA 规范。外部调用行为遵循课程固定的 RISC-V ELF psABI。两个版本在课程运行期间保持固定。

## LLVM IR 和代码生成

学生必须使用 LLVM IR 作为其中间表示，并且能够发出可被 Clang/LLVM 22 针对课程目标接受的有效文本 LLVM IR（`.ll`）。该 IR 必须保留 Rx 语义，并使用与 RV32IM/ILP32 一致的目标三元组和数据布局。

在前端开发期间，学生可以在自己的后端就绪之前，用 Clang 编译此 IR 并在 REIMU 中运行生成的汇编以检查程序行为。完成的编译器必须使用学生实现的后端从 LLVM IR 生成 RISC-V 汇编。Clang 或 LLVM 代码生成可用于验证，但不能替代该后端。

Clang 可以编译 C 运行时，生成的程序可以调用自定义辅助函数。运行时辅助函数不得代替代码生成来解释源程序或 IR。课程工作人员可以使用其他工具来生成参考结果和性能基线。

<details>
<summary>使用 LLVM IR 进行前端验证</summary>

给定前端的 `student.ll` 和课程的 `runtime-example.c`，将两者编译为文本汇编并一起执行：

```sh
clang --target=riscv32-unknown-elf -march=rv32im -mabi=ilp32 \
  -O0 -S student.ll -o frontend-check.s
clang --target=riscv32-unknown-elf -march=rv32im -mabi=ilp32 \
  -O2 -fno-builtin -S runtime-example.c -o runtime.s
reimu --file=frontend-check.s,runtime.s --memory=256M --stack=1M \
  --output=frontend-check.out
```

将 `frontend-check.out` 与预期的源行为进行比较，以独立于学生后端测试前端。该程序从标准输入读取；`--output` 使其输出与 REIMU 的状态消息分开。此检查使用相同的 RV32 目标，包括 32 位地址和 `usize`/`isize`。

</details>

## 数据布局

源整数和地址是 32 位。下表给出参考存储布局；当源行为和外部接口保持正确时，学生实现可以使用另一种内部布局。

| 类型 | 大小（字节） | 对齐（字节） | 表示 |
| --- | ---: | ---: | --- |
| `i32`, `u32` | 4 | 4 | 32 位二进制补码或无符号整数 |
| `isize`, `usize` | 4 | 4 | 与地址宽度相同 |
| `bool` | 1 | 1 | `false = 0`, `true = 1` |
| `&T`, `&mut T` | 4 | 4 | 一个机器地址 |
| `()` | 0 | 1 | 无数据 |

内部寄存器和编译器生成的中间值的表示在其他方面由实现定义，前提是可观察的源行为和所有外部接口都得到保留。引用不携带运行时生命周期信息。单元返回值不使用返回寄存器。

<details>
<summary>参考聚合布局</summary>

课程实现使用以下方便的布局，但学生实现可以选择另一种内部布局：

- `[T; N]` 具有 `T` 的对齐，大小为 `size(T) * N`；元素 `i` 从 `i * size(T)` 开始。
- 结构体字段按声明顺序出现，每个字段位于满足其对齐的第一个偏移处。
- 结构体的对齐是字段对齐的最大值，其大小向上舍入到该对齐。
- 填充字节具有未指定的值，复制值时不需要保留。
- `&[T; N]` 是一个字，而不是切片胖指针。

跨越所选运行时接口的代码必须在两侧使用相同的布局。

</details>

## 调用约定和值语义

普通函数、方法、递归和私有汇编辅助函数可以使用任何一致的内部约定。为方便起见推荐使用 psABI，但仅在诸如机器 `main`、课程 C 运行时和 REIMU libc 等实际外部边界处才要求使用。

psABI 的调用约定规定了参数和返回值的位置、调用者可以期望在调用后保持哪些寄存器，以及栈的对齐方式。对于普通 32 位整数或引用参数，前八个使用 `a0` 到 `a7`，更多参数使用栈；32 位标量结果使用 `a0`。被调用者保留 `s0` 到 `s11` 并恢复 `sp`。如果调用者需要调用者保存寄存器（`a0` 到 `a7`、`t0` 到 `t6` 或 `ra`）中的值在调用后存活，则负责保存和恢复它。在这些外部边界处，栈必须遵循 psABI 的 16 字节对齐规则。链接的规范涵盖聚合参数和其余规则。

机器级间接必须保留源按值语义。例如，在 `fn f(mut x: [i32; 3])` 内部修改参数不得修改调用者的值。当旧值不再可观察时，存储可以在移动后被重用。

方法可以将接收者降低为显式参数。固定大小数组保持源级按值聚合，不经历 C 风格的数组到指针退化。

## 符号、入口和运行时

全局机器符号 `main` 必须提供行为等同于 `int main(void)` 的 C ABI 入口点。它调用源[入口函数](../15-builtin/15.00-builtin.md#program-entry)，并在该调用完成后，在 `a0` 中返回有符号 32 位值 0。它必须遵守 psABI，包括栈对齐和寄存器保留。

推荐的降低方式为源 `main` 提供一个唯一的名字修饰内部符号，并生成一个导出机器符号 `main` 的包装器。对 `main` 的源调用（包括递归调用）以内部源函数为目标，并使用其普通的返回单元调用约定。从该函数返回会恢复其调用者；从包装器返回会正常结束程序。源签名保持为 `fn main() -> ()`。

例如，以下类 C 草图说明了这种拆分：

```c
static void __rx_source_main(void) {
    /* Lowered source main body. */
}

int main(void) {
    __rx_source_main();
    return 0;
}
```

内部符号拼写是说明性的。源和辅助符号名称由实现定义，但必须唯一，且不得与机器入口或运行时符号冲突。源函数可以使用任何受支持的内部调用约定。如果等价降低同时保留普通的返回单元源调用和机器入口契约，则允许使用；发出的代码中不必保留单独的包装器和内部函数。

源 I/O 内建函数使用此 C ABI：

```c
int32_t get_i32(void);
void print_i32(int32_t value);
void println_i32(int32_t value);
```

它们的输入和输出行为由[内建 I/O](../15-builtin/15.00-builtin.md#io-functions)定义。学生可以使用课程运行时或提供兼容的实现。运行时符号恰好链接一次。

## 堆分配接口

使用课程运行时的生成代码通过此固定的 C ABI 分配 `Box` 和 `Vec` 存储，该 C ABI 对源不可见：

```c
void *__rx_alloc(uint32_t size, uint32_t align);
```

`size` 和 `align` 是字节计数。有效调用具有非零大小和对齐 1 或 4。该函数按请求的对齐返回至少 `size` 个可访问字节，与每个尚未被重用的分配不相交。对于有效测试，分配成功；失败行为未指定。

不要求提供 `__rx_dealloc`。自定义运行时可以改为使用私有分配器、调用 REIMU `malloc`，或内联等价行为。在每种情况下，编译器计算类型大小、对齐、元素步长和容器容量，而运行时管理无类型存储。有效的分配计算适合 `usize`，因此不需要动态溢出检查和 panic 支持。

REIMU 还提供 psABI 兼容的 `memcpy`、`memmove` 和 `memset`。仅在已知不相交的范围使用 `memcpy`，当范围可能重叠时使用 `memmove`。

<details>
<summary>建议的编译器/运行时拆分</summary>

| 操作 | 编译器职责 | 运行时职责 |
| --- | --- | --- |
| `Box` 构造 | 求值、计算布局、初始化并返回所有者 | 分配对齐的字节 |
| `Vec` 增长 | 计算容量、维护元数据并移动存活元素 | 分配新缓冲区；可选地提供辅助函数 |
| 按值操作 | 选择复制或移动并保留值语义 | 可选地复制原始字节 |
| 容器克隆 | 递归克隆具体 `T` | 分配结果存储 |
| 程序结束 | 不要求类型化析构 | 回收执行的堆 |

</details>

## 汇编和执行

REIMU 接受文本汇编文件，并在内部汇编、链接和执行它们。如上所示将所选 C 运行时编译为 `runtime.s` 后，使用以下命令运行学生后端的 `student.s`：

```sh
reimu --file=student.s,runtime.s --memory=256M --stack=1M \
  --output=student.out
```

两个汇编输入都是文本 `.s` 文件；程序从标准输入读取并写入 `student.out`。REIMU 解析对其支持的 libc 函数（如 `printf`、`scanf` 和 `malloc`）的调用。不向 REIMU 传递任何目标文件或 ELF 二进制文件。自定义运行时提供自己的汇编来代替 `runtime.s`。

正常的源完成返回状态 0，每个输出字节（包括空白）都是可观察的。

有效程序可能包含超出 12 位有符号立即数范围的整数常量和栈偏移，以及超出单条条件分支指令可达范围的控制流跳转。规范对源大小、编译时间、编译器内存或生成的汇编大小没有单独限制。

提交命令和评分政策属于课程管理，而非语言或执行语义。

## 优化和执行成本

不强制要求任何特定优化。如果栈槽基线能够处理调用、有限寄存器和所有有效控制流，则它是有效的。优化可以改变 IR、寄存器、存储和指令序列，但必须保留可观察的源行为和外部接口。

性能使用固定的 REIMU 版本以其默认权重且不使用改变成本模型的选项报告的 `Total cycles`。计数包括生成的代码、运行时指令和计价的 libc 操作。基线、聚合、分数和排名是单独的评估政策。
