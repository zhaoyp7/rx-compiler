# Rx 编译器规范

欢迎参加 Rx 编译器课程！在本课程中，你需要为我们称为 *Rx* 的 [Rust](https://www.rust-lang.org/) 子集编写一个编译器。编译器将以 [RV32IM](https://en.wikipedia.org/wiki/RISC-V) 指令集架构为目标。为简化前端开发，我们提供了一个用于 Rx 的 [ANTLR v4](https://www.antlr.org/) 文法来自动完成解析，使你能够直接从抽象语法树（AST）开始。

编译器必须使用 LLVM IR 作为其中间表示，并支持将其输出为文本。这样你便可以在实现自己的 RISC-V 后端之前，使用 Clang 验证前端，如[后端](../16-backend/16.00-backend.md#llvm-ir-and-code-generation)中所述。

为了与 Rust 兼容，解析器还接受顶层 `use` 声明和生命周期语法。你可以在[解析后丢弃二者](../04-grammar/04.00-grammar.md#syntax-that-may-be-discarded-after-parsing)；导入解析和生命周期检查不属于本作业的一部分。

本书严格定义了 Rx 的语法和语义，并与官方 Rust 编译器（`rustc`）一起构成本课程的权威依据。如果你发现二者之间存在任何歧义或不一致，请随时联系你的助教以获取澄清。

## 如何阅读本规范

首先阅读[语言范围与测试保证](../01-undefined-behavior/01.00-undefined-behavior.md)，其中区分了有效程序、编译错误和排除的情形（即*未定义行为*），以了解哪些特性是必需的、哪些超出范围。

接下来，继续阅读[词法结构](../03-lexical-structure/03.00-lexical-structure.md)，然后是[项](../07-items/07.00-items.md)、[类型](../10-types/10.00-types.md)和[表达式](../11-expressions/11.00-expressions.md)。这些章节定义了 Rx 语言的完整文法。[文法摘要](../17-grammar-summary/17.00-grammar-summary.md)一节中有一张快速查阅表。

阅读时，我们建议动手试用 Rust 编译器（`rustc`）。你也可以使用 [Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024) 或 [Compiler Explorer](https://godbolt.org/) 等在线环境，观察哪些代码可以编译、哪些不能。请注意，我们**不将编译器警告视为编译错误**。

## 如何开始

在开始之前，我们建议你先复习一份 Rust 入门教程。你无需全面掌握，因为 Rx 只实现了其中一个子集，但熟悉基本的 Rust 语法是必不可少的。

有许多优秀的在线资源讲解了编译器构建的各个阶段。你的助教（或他们助教）的一些博客包括：

- [Compiler for Mx* 编译器随笔](https://darksharpness.top/CompilerMx/)：由传奇助教 [@darksharpness](https://darksharpness.top/) 撰写：一篇经典博文，重点介绍了 Mx（Rx 之前使用的课程语言）中的各种优化技术。
- [Writing a Compiler for Rust](https://norb.space/blog/writing-a-compiler-for-rust)：由 RayZh（本规范的共同设计者）撰写：主要关注端到端的编译器流水线。请注意，由于今年规范的更新，其中讨论的某些技术已不再需要或不再适用。

补充信息：

- [Compiler 101](https://github.com/ACMClassCourses/Compiler-101)：ACM 班学生多年来的项目和笔记合集。请注意，其中描述的许多技术是 Mx 特有的，可能不适用于 Rx。
- [The Rust Reference](https://doc.rust-lang.org/reference/)：Rust 语言的官方全面参考。虽然本 Rx 规范意在自包含，但 Rust Reference 是标准 Rust 语义的权威补充指南。
- [Rust Compiler Development Guide](https://rustc-dev-guide.rust-lang.org/)：一份关于 `rustc` 内部机制与架构的高级深入指南，推荐作为编译器工程模式的背景参考。
