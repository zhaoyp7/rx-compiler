# 语言范围与测试保证

## 定义

我们区分有效程序、编译错误和未定义行为：

| 类别 | 编译器要求 | 测试策略 |
| --- | --- | --- |
| 有效程序 | 编译并产生指定的行为 | 可出现在任何适用的测试中 |
| 编译错误 | 正常拒绝；诊断措辞未作规定 | 可出现在负面测试中 |
| 未定义行为 | 无要求的诊断或行为 | 按其定义规则所述予以排除 |

即使所提供的解析器能够识别不支持的语法，也允许在语言子集边界处将其拒绝。除非某种源码形式被明确归类为未定义行为，否则普通的名称、类型和位置可变性错误仍然是编译错误，包括在不可达代码中。编译器无需证明终止性、借用有效性或所有权有效性。对于被排除的执行，不要求运行时检查、panic 处理和栈展开。

## 语言子集

Rx 是 Rust 2021 的一个子集。每个 Rx 源程序都使用合法的 Rust 语法，但本规范定义了自己的内建环境和所需的运行时行为。

Rx 包括：

- 函数、命名字段结构体、常量和固有实现。
- 用于 Rust 兼容性的顶层 [use 声明](../07-items/07.01-use-declarations.md)，解析后忽略。
- 标识符绑定和局部类型推断。
- 整数、布尔值、固定数组、引用以及内建 `Box` 和 `Vec` 容器。
- `if`、`while`、`loop`、`return`、`break` 和 `continue` 控制流。
- 对 `Copy`、`Clone`、`PartialEq` 和 `Eq` 的结构体派生。

Rx 子集不包括：

- 用户 trait、trait 约束和 trait 对象。
- 枚举、非单元元组、元组结构体、元组变体和单元变体。
- 模式匹配、解构和守卫。
- 类型参数和一般泛型。支持生命周期语法，但其有效性是被保证的，而不是被检查的。
- 模块声明和导入解析、可见性、私有性、宏和任意属性。仅按 [use 兼容性保证](#use-compatibility)所述接受 use 声明。
- 除此处定义的内建项之外的 unsafe Rust 和标准库。
- const 泛型和超出受限[常量上下文](../12-const_eval/12.00-const_eval.md)的一般常量求值。常量传播仍然是一个可选的优化。
- 整数溢出检查。

[类型](../10-types/10.00-types.md)、[表达式](../11-expressions/11.00-expressions.md)和[文法摘要](../17-grammar-summary/17.00-grammar-summary.md)定义了完整的子集。该文法之外的形式不受支持。

## 测试保证

以下源码形式会触发未定义行为，永远不会出现在测试套件中，包括在适用情况下的不可达代码或常量上下文内：

| 未定义行为 | 定义规则 |
| --- | --- |
| 超出其确定类型的整数字面量 | [整数字面量范围](#integer-literal-range) |
| 需要在二元运算、一元运算或共享/可变借用中通过期望类型传播的整数推断 | [期望类型传播](../10-types/10.00-types.md#coercion-sites-and-expected-types) |
| 在 `Box::new(...)` 或 `Vec::new()` 构造函数调用中省略显式具体类型实参 | [内建构造函数](../14-heap/14.00-heap.md#builtin-signatures) |
| 将函数用作值 | [函数值](../11-expressions/11.02-path-expr.md#function-values) |
| 声明名为 `u32`、`isize`、`usize`、`bool`、`Box`、`Vec`、`Copy`、`Clone`、`PartialEq` 或 `Eq` 的结构体 | [受保护的内建名称](../06-names/06.00-names.md#protected-builtin-names) |
| 名为 `get_i32`、`print_i32` 或 `println_i32` 的局部绑定 | [受保护的内建名称](../06-names/06.00-names.md#protected-builtin-names) |
| 不可达代码中的位置可变性违规，包括赋值、可变借用或可变接收者调整 | [不可达代码](../10-types/10.05-never.md#unreachable-code) |
| 具有 never 类型 `!` 的数组或 `Vec` 索引操作数 | [索引操作数类型](../11-expressions/11.07-array-expr.md#index-operand-types) |
| 文档注释（`///`、`//!`、`/**`、`/*!`） | [文档注释](../03-lexical-structure/03.04-comments.md#documentation-comments) |
| let 或参数名与可见的非限定常量冲突 | [常量名冲突](#constant-name-collisions) |
| 不同源类型之间的相等比较 | [跨类型相等比较](#cross-type-equality) |
| 两个类型都无法成为公共目标的最小上界强制转换 | [最小上界强制转换](../10-types/10.00-types.md#least-upper-bound-coercions) |
| 点调用中存在多个不同的匹配方法 | [方法查找](../11-expressions/11.10-method-call-expr.md#method-lookup) |
| 违反 Rust 兼容性保证的 use 声明 | [use 兼容性](#use-compatibility) |
| 无效的生命周期声明、使用、约束或省略 | [生命周期有效性](#lifetime-validity) |
| 单元结果例外之外的可观察零大小数据使用 | [零大小数据](#zero-sized-data) |

这些保证约束有效源程序。编译期间引入的任何无效内存访问、错误终止或错误程序输出仍然是编译器缺陷。

### 整数字面量范围

整数字面量的类型按后缀、期望整数类型或 `i32` 回退的顺序选择。当在没有期望类型的情况下求值时，值超出 `i32` 范围的无后缀整数字面量构成未定义行为。

整数字面量溢出表现为未定义行为。[字面量规则](../11-expressions/11.01-literal-expr.md#integer-typing-and-range)仍然允许有符号最小值，如 `-2147483648i32` 和 `-(2147483648i32)`。

### 常量名冲突

名称与可见的非限定常量匹配的 `let` 绑定或函数参数会触发未定义行为，无论可变性或声明顺序如何。不需要任何诊断或常量模式解释。只能通过 `Type::NAME` 访问的关联常量不排除局部 `NAME`。与内建名称的冲突遵循[受保护的内建规则](../06-names/06.00-names.md#protected-builtin-names)。

### 跨类型相等比较

对源类型不同的操作数应用 `==` 或 `!=` 会触发未定义行为。不需要诊断、强制转换或跨类型 `PartialEq` 实现。这包括共享引用与可变引用、不同数组类型、不同容器元素类型，以及 `Vec` 与数组的比较。

[相等规则](../08-traits-and-attributes/08.01-builtin-traits.md#partialeq)定义了操作数类型、能力要求以及同类型比较。根据[类型同一性](../10-types/10.00-types.md#supported-types)，仅生命周期实参本身不区分源类型。

### use 兼容性

测试可能包含 [use 声明](../07-items/07.01-use-declarations.md)，例如
`use rx::core::*;`，以便用 Rust 和课程支持 crate 编译同一份源码。它们的导入路径和组合在该 Rust 环境中是有效的。
程序使用的任何导入名称都按现有拼写表示一个 Rx 内建项；允许未使用的导入和别名。测试从不依赖 use
声明向 Rx 引入另一种类型、值、模块或可用别名。

违反这些保证构成未定义行为，不会出现在
任何正面、负面或性能测试中。编译器无需解析导入，
也无需诊断缺失的导入项、冲突的导入或其他导入有效性错误。
格式错误的 use 语法仍必须由解析器以标准语法错误拒绝。
在丢弃 use 声明之后，程序中其他位置的普通名称、类型和位置可变性错误
仍然是编译错误。

### 生命周期有效性

生命周期声明、标注、实参、约束和省略遵循[引用](../13-references/13.00-references.md#lifetime-validity)中所述受支持的 Rust 2021 规则。测试保证它们在程序中始终有效。无效的生命周期使用是未定义行为，不会出现在任何正面、负面或性能测试中。

编译器可以在解析后丢弃这些生命周期语法，无需将其带入语义分析或 LLVM IR 生成。[解析器约定](../04-grammar/04.00-grammar.md#syntax-that-may-be-discarded-after-parsing)说明了哪些信息仍然是必需的。

<details>
<summary>被排除的生命周期错误</summary>

测试排除未声明或重复的生命周期、无效的遮蔽、错误的实参数量或位置、被禁止的显式晚绑定实参、有歧义的缺失标注、未满足的 outlives 约束、无效的 `'static` 声明、被拒绝的未使用参数，以及未能兑现其标注的函数体或使用。

格式错误的词法单元和语法保留其通常的词法分析器和解析器行为。其他类型和位置可变性错误仍然是编译错误。不要求生命周期或所有权检查器；实际引用仍必须遵守[借用规则](../13-references/13.00-references.md#borrowing-rules)。

</details>

### 零大小数据

单元 `()` 作为函数或控制流结果是有效的。

<details>
<summary>被排除的零大小使用</summary>

所有其他需要可观察零大小存储的使用都是未定义行为，包括：

- 零大小参数、绑定、常量、静态项或赋值目标。
- 空结构体或零大小字段。
- 零长度数组或零大小数组元素。
- 对零大小值的引用以及对零大小数据的解引用。

</details>

元素类型 `T` 非零大小的空 `Vec<T>` 是有效的，其本身不是零大小。其表示由实现定义。

资源限制、栈大小、分配策略和输出约束是[后端契约](../16-backend/16.00-backend.md#resource-guarantees)的一部分。
