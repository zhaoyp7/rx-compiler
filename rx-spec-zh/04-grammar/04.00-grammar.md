# 解析器约定

语言文法由各章节中的 Lexer 和 Syntax 块定义。[文法摘要](../17-grammar-summary/17.00-grammar-summary.md)将这些相同的产生式汇集在一处。本指南索引了优先级和表达式边界的规则，并规定了上下文相关的词法单元解释。

<details>
<summary>按源码形式划分的文法覆盖范围</summary>

每次出现 [Type] 或 [Expression] 都允许其各自产生式中定义的所有备选项。这种组合递归适用：结构体字段可以持有诸如 `Vec<Box<T>>` 的嵌套容器类型，构造函数实参可以包含一个块，构造函数结果可以继续串接索引或方法调用。

| 源码形式 | 定义产生式 | 示例 |
| --- | --- | --- |
| 标识符和整数 | [IDENTIFIER], [INTEGER_LITERAL] | `_value`, `123_i32`, `0b1010` |
| 生命周期词法单元和形式 | [LIFETIME_TOKEN], [Lifetime] | `'a`, `'static`, `'_` |
| 生命周期参数和约束 | [GenericParams], [LifetimeParam], [WhereClause] | `fn f<'a>(x: &'a i32)`, `where 'a: 'b` |
| 源码编译单元 | [Crate], [Item] | 顶层 use 声明、函数、结构体、常量、impl |
| use 声明 | [UseDeclaration], [UseTree], [UsePath] | `use rx::core::*;`, `use rx::core::{get_i32, println_i32};` |
| 函数和接收者 | [Function], [FunctionParameters], [ShorthandSelf] | `fn f(v: Vec<i32>) -> Box<i32> { ... }`, `&mut self` |
| 结构体声明与构造 | [StructStruct], [StructExpression] | `struct S { x: i32 }`, `S { x: 1 }`, `Self { x: 1 }` |
| 关联项 | [InherentImpl], [AssociatedItem] | `impl S { fn new() -> Self { ... } }` |
| 派生属性 | [OuterAttribute], [DeriveAttribute] | `#[derive(Clone, PartialEq, Eq)]` |
| 绑定和语句 | [LetStatement], [ExpressionStatement] | `let mut v = Vec::<i32>::new();`, `v.push(1);` |
| 类型名、数组、引用和单元 | [TypePath], [ArrayType], [ReferenceType], [UnitType] | `Self`, `[Vec<i32>; 2]`, `&mut Box<i32>`, `()` |
| 容器类型 | [TypePath], [TypePathSegment], [GenericArgs] | `Box<[i32; 4]>`, `Vec<Box<Node>>`, `Vec<Vec<i32,>,>` |
| 容器构造 | [CallExpression], [PathInExpression] | `Box::<i32>::new(7)`, `Vec::<Box<i32>>::new()` |
| 路径、调用、字段和索引 | [PathExpression], [CallExpression], [MethodCallExpression], [FieldExpression], [IndexExpression] | `S::new()`, `value.clone()`, `value.field`, `values[0]` |
| 数组、分组和单元值 | [ArrayExpression], [GroupedExpression], [UnitExpression] | `[1, 2, 3]`, `[0; 4]`, `(value)`, `()` |
| 运算符 | [OperatorExpression] | `*p`, `&mut values[0]`, `a + b`, `x += &y` |
| 块和分支 | [BlockExpression], [IfExpression] | `{ make() }.field`, `if flag { a } else { b }` |
| 循环和跳转 | [LoopExpression], [BreakExpression], [ContinueExpression], [ReturnExpression] | `loop { break 3; }`, `while condition { ... }`, `return value` |
| 常量上下文 | [ConstValue], [Magnitude] | `123`, `COUNT`, `(-1)`, `-(2147483648i32)`, `((true))` |

文法描述构造的形状。名称解析、类型检查、位置可变性以及[测试域](../01-undefined-behavior/01.00-undefined-behavior.md)决定哪些已解析程序是有效的。例如，结构体构造表达式中的标识符必须命名一个已声明的结构体，被调用的方法必须在接收者类型的固有实现中定义，赋值目标必须表示一个可变位置。

</details>

## 解析后可以丢弃的语法

两种形式的 Rust 兼容性语法必须被解析，但不需要后续的语义处理或 LLVM IR 表示：

- [use 声明](../07-items/07.01-use-declarations.md)：丢弃整个声明。不需要导入解析、模块加载、别名插入或导入冲突检查。
- 生命周期语法：丢弃生命周期参数声明、引用生命周期标注、显式生命周期实参、outlives 约束和生命周期 where 子句。不需要生命周期名称解析、推断、省略检查或生命周期/借用检查器。

[use 兼容性](../01-undefined-behavior/01.00-undefined-behavior.md#use-compatibility)和[生命周期有效性](../01-undefined-behavior/01.00-undefined-behavior.md#lifetime-validity)保证排除了需要这些检查的测试。丢弃生命周期语法是一种内部 AST 变换；编译器不需要确保剥离生命周期标注后的源文本构成合法的 Rust。

解析仍必须强制执行这些构造的文法。编译器必须保留引用类型、可变性限定符、具体类型实参（例如 `Vec::<&'a i32>` 中的 `i32`）以及所有其他 AST 结构。普通的名称、类型和位置可变性检查以及正确的引用行为仍然是必需的。

## 上下文标点

解析器根据其当前文法上下文解释组合标点。词法分析器可以输出一个组合词法单元；解析器消费所需的前缀，并将剩余标点留给外层构造。

| 组合词法单元 | 上下文 | 解释 |
| --- | --- | --- |
| `&&` | 引用类型或前缀借用 | 两个 `&` 词法单元，如 `&&i32` 或 `&&x` |
| `>>` | 关闭嵌套类型实参 | 两个关闭的 `>` 词法单元 |
| `>=` | 赋值前关闭类型实参 | 一个关闭的 `>` 后跟 `=` |
| `>>=` | 赋值前关闭嵌套类型实参 | 两个关闭的 `>` 词法单元后跟 `=` |

在普通中缀表达式上下文中，这些词法单元表示其对应的运算符。因此，以下变量初始化在关闭的 `>` 和 `=` 词法单元之间不需要空白：

```rust,ignore
let values: Vec<i32>=Vec::<i32>::new();
let nested: Vec<Vec<i32>>=Vec::<Vec<i32>>::new();
```
