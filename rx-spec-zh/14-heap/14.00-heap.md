# Box 与 Vec

[Box 和 Vec 类型](../10-types/10.03-heap.md)一章定义了容器表示和类型规则。本章定义它们的操作、引用语义和分配生命周期。[能力表](../08-traits-and-attributes/08.01-builtin-traits.md#trait-capability-summary)定义了 `Copy`、`Clone` 和相等性支持。

## 内建签名

在这些签名中，`T` 表示容器的具体类型实参。
`&self` 获取容器的共享引用；`&mut self` 获取可变
引用。`new` 是没有接收者的关联函数。其他条目是方法，并
遵循普通的[方法调用规则](../11-expressions/11.10-method-call-expr.md)。
此表中的任何操作都不需要 `T` 的内建 trait 能力；
实参遵循普通的[调用和强制转换规则](../11-expressions/11.09-call-expr.md)。

| 容器 | 签名 | 行为 |
| --- | --- | --- |
| `Box<T>` | `fn new(value: T) -> Box<T>` | 将 `value` 移动或复制到新的拥有所有权的存储中。 |
| `Vec<T>` | `fn new() -> Vec<T>` | 创建一个空向量。 |
| `Vec<T>` | `fn len(&self) -> usize` | 返回已初始化元素的数量。 |
| `Vec<T>` | `fn is_empty(&self) -> bool` | 返回长度是否为零。 |
| `Vec<T>` | `fn push(&mut self, value: T) -> ()` | 通过复制或移动追加一个元素。 |
| `Vec<T>` | `fn remove(&mut self, index: usize) -> T` | 移出并返回索引处的元素，将后续元素左移。 |

在有效程序中，构造函数具有显式的具体类型实参：

```rust,ignore
let boxed = Box::<i32>::new(7);
let mut values = Vec::<i32>::new();
```

所有容器构造函数——包括嵌套的构造函数——都必须提供显式的具体类型实参。
省略此实参，如 `Box::new(7)` 或 `Vec::new()`，在[测试保证](../01-undefined-behavior/01.00-undefined-behavior.md#test-guarantees)下是未定义
行为。`T` 内部的生命周期实参遵循[生命周期规则](../13-references/13.00-references.md#lifetime-validity)；
不支持类型位置的 `_`。

## Box 访问和移动

对于 `b: Box<T>`，内建解引用表达式 `*b` 是一个 `T` 位置。
它通过可变所有者或可变引用可变更，通过共享访问
只读。在受支持的 `Box` 和引用解引用之后，普通的字段、索引、方法和借用
操作适用。

解引用拥有的 `Box` 不会插入共享借用。不可变所有者
会阻止替换其内容，但存储在这些内容中的 `&mut U` 仍
可提供对 `U` 的可变访问。通过 `&Box<T>` 的访问跨越共享
引用，无法提供这种可变访问。

读取 `Copy` 内容会复制它们。从拥有的 `Box` 读取非 `Copy`
内容会移动它们；通过借用的 `Box` 移动被所有权保证排除。内容已被移动的分配可以保持已分配状态直到程序结束。

## Vec 操作

对于 `v: Vec<T>` 和 `index: usize`，内建索引表达式 `v[index]`
是一个 `T` 位置。

索引和移除要求 `index < len`；越界执行被排除，不要求检查或 panic。`remove` 保持顺序，并支持非 `Copy`、非 `Clone` 元素。读取 `Copy` 索引元素会复制它；直接移动非 `Copy` 索引元素是未定义行为（被测试保证排除），因此必须使用 `remove` 提取元素。支持对可变索引位置的赋值。

```rust,ignore
let mut v = Vec::<i32>::new();
v.push(10);
v.push(20);
let first = v[0];               // copying an i32 element
let removed = v.remove(0);      // removing element at index 0
```

`Vec` 本身不可解引用，且永远不会强制转换为元素或切片
引用。

### 索引和可变访问

`Vec` 索引会隐式借用该向量。共享读取和
[`&mut T` 到 `&T` 的强制转换](../10-types/10.00-types.md#coercion-types)只需要共享访问。
赋值、复合赋值、可变借用或
重借用，以及 `&mut self` 接收者在该索引步骤需要对该向量的可变访问。

该要求贯穿字段、进一步索引、`Box` 解引用
以及存储在元素中的可变引用。向量内部的 `&mut T` 不会
使不可变向量变为可变：

```rust,ignore
fn shared_access(values: Vec<&mut i32>) {
    let r: &i32 = values[0]; // valid: &mut i32 coerces to &i32
}

fn immutable_vector(values: Vec<&mut i32>) {
    *values[0] = 2; // compile error: add mut to the values parameter
}

fn mutable_vector(mut values: Vec<&mut i32>) {
    *values[0] = 2; // valid: the vector can be borrowed mutably
}

fn mutable_reference(values: &mut Vec<&mut i32>) {
    *values[0] = 2; // valid: the reference supplies mutable access
}
```

即使没有对元素的显式赋值，可变重借用和方法接收者也需要同样的可变访问。
下面两个函数都需要 `mut values`：

```rust,ignore
fn mutable_reborrow(values: Vec<&mut i32>) {
    let r: &mut i32 = values[0]; // compile error
}

fn nested_method(values: Vec<Vec<i32>>) {
    values[0].push(2); // compile error: push needs a mutable receiver
}
```

固定数组索引和拥有的 `Box` 解引用不会插入容器
借用。因此存储在那里的可变引用可以通过
不可变所有者继续使用。可变引用的位置很重要：

```rust,ignore
fn array_reference(values: [&mut i32; 1]) {
    *values[0] = 2; // valid, unlike immutable_vector above
}

fn boxed_reference(value: Box<&mut i32>) {
    **value = 2; // valid: dereferencing the stored mutable reference
}

fn boxed_vector(values: Box<Vec<&mut i32>>) {
    *values[0] = 2; // compile error: the vector has an immutable owner
}

fn boxed_vector_reference(values: Box<&mut Vec<&mut i32>>) {
    *values[0] = 2; // valid: mutable access is obtained before Vec indexing
}
```

## Clone 与相等性

当 `T` 是 `Clone` 时，容器支持这些内建 `Clone` 方法：

| 类型 | 方法签名 | 结果 |
| --- | --- | --- |
| `Box<T>` | `fn clone(&self) -> Box<T>` | 将存储的 `T` 克隆到独立拥有所有权的存储中。 |
| `Vec<T>` | `fn clone(&self) -> Vec<T>` | 按顺序将元素克隆到等长的独立向量中。 |

拥有的嵌套容器递归克隆；共享引用被复制而不克隆其目标。`Clone` 能力在[内建 trait](../08-traits-and-attributes/08.01-builtin-traits.md#clone)中规定。
如果多个方法匹配相同的候选接收者类型，点调用仍受[竞争方法排除](../11-expressions/11.10-method-call-expr.md#method-lookup)约束。诸如 `Box::<i32>::clone(&boxed)` 的完全限定调用直接选择容器操作，无需方法查找。

`Box` 相等性比较存储的值。`Vec` 相等性比较长度和对应元素，忽略分配地址、容量和填充。这些操作可与结构体派生以及递归类型的有限值组合。

## 存储和引用

`Vec` 恰好存储其已初始化的序列；备用容量不是已初始化数据。容量和增长是不可观察的实现选择。重新分配保留值和顺序，但会使指向旧缓冲区的引用失效。`remove` 会使指向被移除或被移动元素的引用失效。

测试遵守 Rust 的借用规则，包括受支持的两阶段接收者借用，例如 `v.push(v.len())`。它们绝不会跨越冲突的可变容器操作使用元素引用，无论备用容量如何。不要求借用检查器。

零大小堆对象在[零大小数据保证](../01-undefined-behavior/01.00-undefined-behavior.md#zero-sized-data)下是未定义行为。对于非零大小的 `T`，空 `Vec<T>` 是有效的，且不需要有可解引用的缓冲区。有效测试中的所有分配都适合目标的 32 位 `usize` 地址空间，且测试用例不依赖分配失败。

## 堆清理

学生生成的代码不需要释放堆分配。允许堆泄漏：来自 `Box` 和 `Vec` 的存储可以在作用域退出、覆盖、移出、返回、跳转或 `Vec` 缓冲区替换之后保持已分配状态。不要求逐值析构、释放调用或最终堆清理代码。

这不会改变源所有权或引用有效性。移动仍然转移所有权，克隆仍然创建独立拥有所有权的内容，并且因重新分配或移除而失效的引用即使旧字节仍然存在也仍然无效。

当实现保持程序行为和有效引用时，可以更早地回收或重用存储。测试适合[后端资源保证](../16-backend/16.00-backend.md#resource-guarantees)定义的累计堆预算。
