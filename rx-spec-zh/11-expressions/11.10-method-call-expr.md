# 方法调用表达式

r[expr.method.syntax]
```grammar,expressions
MethodCallExpression -> Expression `.` PathExprSegment `(` CallParams? `)`
```

方法调用给出一个接收者表达式、一个方法标识符和一个带括号的参数列表。最后一个参数之后可以有一个可选的尾随逗号。

[PathExprSegment] 提供共享的路径段语法。方法使用其标识符以及 Rust 允许的可选生命周期参数。[路径解析](../06-names/06.01-paths.md#path-resolution)规定了这些参数以及生命周期有效性保证。方法段上的类型参数是编译错误。

## 方法查找

在查找之前，接收者类型必须是已知的。方法调用按如下方式找到接收者调整：

1. 从接收者表达式的类型开始，反复解引用引用和 `Box`，按顺序记录每个类型。`Vec` 不添加解引用步骤。
2. 在每个记录的类型 `T` 之后立即插入 `&T` 和 `&mut T` 作为候选接收者类型。
3. 按该顺序访问候选接收者类型。对于每个候选者：
   - 如果有多个不同的方法匹配该候选者（例如固有方法和派生的内建 `Clone` 方法共享相同的接收者类型），则该调用表现出未定义行为。
   - 如果恰好有一个方法匹配该候选者，则选择它并终止候选搜索。包括固有方法、可用的内建 `Clone` 方法，以及指定的数组和容器方法。
   - 如果没有方法匹配该候选者，则继续到列表中的下一个候选者。
4. 如果列表中没有候选者匹配任何方法，则编译失败并产生编译错误。参数类型、期望结果类型和接收者可变性不会过滤方法是否匹配。
5. 对于选择的方法，应用解引用以及该候选者的任何借用；已有的可变引用接收者可以在[普通引用规则](../10-types/10.00-types.md#mutable-reference-reborrowing)下重新借用。然后检查接收者可变性和普通参数。如果任何检查失败，则编译失败并产生编译错误，但受单独的所有权和生命周期测试保证约束。

测试排除同一候选者上的竞争方法；编译器无需检测它们，也无需实现 Rust 的固有方法优先于 trait 方法的优先级。重复的固有声明仍然是[名称错误](../06-names/06.00-names.md#name-collisions)；接收者候选列表之外的不相关类型上的方法不会竞争。

<details>
<summary>接收者和 clone 示例</summary>

对于 `Box<S>`，候选接收者类型为 `Box<S>`、`&Box<S>`、`&mut Box<S>`、`S`、`&S` 和 `&mut S`。对于 `S` 上接受 `&self` 的唯一方法，在 box 上调用它会解引用到 `S` 并借用该位置。`&mut self` 方法需要根据[位置规则](11.00-expressions.md#places-and-values)对到达的 `S` 位置进行可变访问。

如果 `S` 派生 `Clone` 且没有固有 `clone` 方法，则对 `s: S` 调用 `s.clone()` 会匹配候选者 `&S` 并返回 `S`。同样，对 `r: &S` 调用 `r.clone()` 会直接匹配候选者 `&S`，而不检查 `&&S`，返回 `S`。

然而，如果 `S` 派生 `Clone` 并且还声明了名为 `clone` 的固有方法（例如 `fn clone(&self)`），则对 `s: S` 调用 `s.clone()` 会导致未定义行为，因为固有方法和派生的 trait 方法都匹配候选者 `&S`。

类似地，对于 `b: Box<i32>`，候选者 `&Box<i32>` 会在到达 `i32` 的候选者之前匹配 `Box::<i32>::clone`，将容器克隆到新的 `Box<i32>` 中。

</details>

显式的 `Type::method(receiver, ...)` 调用选择该类型的关联操作，并使用[普通参数强制转换](11.09-call-expr.md)，而不是接收者查找或自动引用。如果该确切类型上的固有方法和内建方法共享同一名称，则选择固有方法。可用的内建操作参见[内建 trait](../08-traits-and-attributes/08.01-builtin-traits.md#clone)和[堆](../14-heap/14.00-heap.md)。
