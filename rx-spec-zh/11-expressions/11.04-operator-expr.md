# 运算符

```grammar,expressions
OperatorExpression ->
      BorrowExpression
    | DereferenceExpression
    | NegationExpression
    | ArithmeticOrLogicalExpression
    | ComparisonExpression
    | LazyBooleanExpression
    | TypeCastExpression
    | AssignmentExpression
    | CompoundAssignmentExpression
```

## 算术与位运算

```grammar,expressions
NegationExpression ->
      `-` Expression
    | `!` Expression

ArithmeticOrLogicalExpression ->
      Expression `+` Expression
    | Expression `-` Expression
    | Expression `*` Expression
    | Expression `/` Expression
    | Expression `%` Expression
    | Expression `&` Expression
    | Expression `|` Expression
    | Expression `^` Expression
    | Expression `<<` Expression
    | Expression `>>` Expression
```

算术运算符 `+`、`-`、`*`、`/` 和 `%` 作用于兼容的整数操作数，不进行隐式整数转换。一元负号要求有符号整数。按位 `&`、`|`、`^` 和 `!` 作用于整数；它们也提供非短路的布尔运算。布尔 `!` 对 `bool` 操作数执行逻辑取反。

基本算术和位运算支持下表中的标量和引用操作数。T 表示一种受支持的标量类型，I 表示一种受支持的有符号整数类型，L/R 表示独立选择的受支持整数类型。

| 运算 | 操作数类型 | 结果 |
| --- | --- | --- |
| 二元算术 `+`、`-`、`*`、`/`、`%` | 每个操作数是 T 或 &T，两侧为相同的整数 T | T |
| 二元位运算 `&`、<code>&#124;</code>、`^` | 每个操作数是 T 或 &T，两侧为相同的整数或 bool 类型 T | T |
| 移位 `<<`、`>>` | 左侧是 L 或 &L；右侧是 R 或 &R | L |
| 一元 `-` | I 或 &I | I |
| 一元 `!` | T 或 &T，其中 T 为整数或 bool | T |
| 算术/位复合赋值 | 基本类型 T 的可变位置；右侧是相应运算的 T 或 &T | 单元 |
| 移位复合赋值 | 基本整数类型 L 的可变位置；右侧是 R 或 &R | 单元 |

期望类型不会穿过二元或一元运算符传播到其操作数。为进行整数推断而需要这种传播的程序表现出[未定义行为](../10-types/10.00-types.md#coercion-sites-and-expected-types)。例如，`let n: u32 = 1 + 2;` 和 `let n: isize = -1;` 是未定义行为；写成 `1u32 + 2u32` 和 `-1isize` 则显式提供了类型。

复合赋值同样不会从目标推断右操作数的整数类型。对于 `n: u32`，`n += 1;` 需要这种推断，属于未定义行为；当 `n` 可变时，`n += 1u32;` 是有效的。表中的所有操作数要求仍然适用。

<summary>引用操作数细节</summary>

这些算术/位运算的引用变体接受一层共享引用，而不是任意的自动解引用。例如，对于兼容的基本类型，支持 `&a + &b`、`-&a` 和 `x += &y`；不支持 `&&a + &b`、`-&mut a` 和 `x += &mut y`。可变引用操作数可以被显式解引用以获得标量值。引用值的赋值目标不会被自动解引用：使用 `*p += rhs` 来更新 p 背后的基本类型值。

这些运算计算标量结果；它们不会仅仅因为某个操作数是引用就改变被引用对象。对引用操作数求值会得到其引用值；运算所需的标量加载在操作数求值之后、执行该运算时发生。复合赋值的顺序在下面规定。

所有受支持的整数都是 32 位。运行时的加法、减法、乘法和有符号取负使用二进制补码算术回绕，如同 Rust 禁用了溢出检查。优化和未优化的代码具有相同行为。除非编译器已针对特定运算证明不会溢出，否则 LLVM 溢出标志不得断言不溢出。

有符号除法向零截断；非零余数的符号与被除数相同。除数为零的除法或取余运算，或者有符号最小整数（`-2147483648i32`）被 -1 除或对 -1 取余的运算，都被排除在有效执行之外。不要求进行检查或 panic 运行时。

移位接受类型可以不同的整数操作数。结果具有左操作数的类型。在运行时，移位量被掩码到其最低有效的 5 位。有符号右移是算术右移；无符号右移是逻辑右移。这种掩码也适用于常量折叠的普通表达式。

## 比较与逻辑

```grammar,expressions
ComparisonExpression ->
      Expression `==` Expression
    | Expression `!=` Expression
    | Expression `>` Expression
    | Expression `<` Expression
    | Expression `>=` Expression
    | Expression `<=` Expression

LazyBooleanExpression ->
      Expression `||` Expression
    | Expression `&&` Expression
```

相等运算符使用 [PartialEq 和相等规则](../08-traits-and-attributes/08.01-builtin-traits.md#partialeq)，包括操作数类型、隐式借用和结构化比较。不同源类型之间的相等比较是未定义行为；请参阅[跨类型相等保证](../01-undefined-behavior/01.00-undefined-behavior.md#cross-type-equality)。

标量排序在匹配的整数类型和 bool 上使用 `<`、`<=`、`>`、`>=`（false 排在 true 之前）。引用操作数比较目标值，而不是地址。它们的引用层必须在每一深度具有匹配的可变性，并以相同的受支持标量类型结尾。还支持一种额外的操作数组合：类型为 `&T` 的左操作数允许类型为 `&mut T` 的右操作数，后者被调整为 `&T`，且被引用类型恰好为相同的 `T`。这种特定于运算符的调整不依赖于期望的结果类型，也不会改写内层引用层。

例如，对于匹配的有序标量，`&a < &b`、`&mut a < &mut b` 和 `&a < &mut b` 可以工作；`&mut a < &b` 和 `&&a < &&mut b` 不行。既不存在值与引用之间的自动比较（如 `a < &b`），也不存在为了排序而通过 `Box` 进行的自动解引用。

`&&` 和 `||` 要求 bool 值，返回 bool，并从左到右短路。它们没有引用操作数变体：`&true && true` 无效。不存在整数的真值性。诸如 `a < b < c` 这样的链式比较不允许直接使用；它们需要显式圆括号和兼容的中间类型（例如 `(a < b) < c`，其中 `a < b` 求值为 `bool`），或者逻辑合取（`a < b && b < c`）。

## 强制转换

```grammar,expressions
TypeCastExpression -> Expression `as` TypeNoBounds
```

`as` 支持整数到整数的强制转换和 bool 到整数的强制转换。由于所有整数都是 32 位，整数强制转换保留 32 位模式并按目标符号性解释它。false 变为 0，true 变为 1。不支持整数到 bool 和引用到整数的强制转换。强制转换目标不会向其操作数提供期望类型：在 `1 as u32` 中，字面量是 `i32`，强制转换产生 `u32`。

### 强制转换解析

<details>
<summary>区分泛型实参与运算符</summary>

[运算符优先级表](11.00-expressions.md#precedence)决定表达式的嵌套。在强制转换中的类型路径段之后，`<` 开始 [GenericArgs] 而不是比较。来自 `<<` 的前导 `<` 同样进入类型实参解析。给强制转换加上圆括号可以明确预期的运算：`(x as usize) < y` 和 `(x as usize) << y`。带圆括号的类型已经结束类型语法，因此 `x as (usize) < y` 和 `x as (usize) << y` 也会解析为比较和移位。`<=`、`>`、`>>` 和 `==` 等运算符在强制转换类型之后遵循普通优先级。

解析器检查生成的语法；名称解析检查其类型实参。因此 `x as usize<i32>` 具有类型路径语法树，但却是编译错误，因为基本类型 usize 不接受类型实参。

</details>

## 借用、解引用与赋值

```grammar,expressions
BorrowExpression ->
      (`&` | `&&`) Expression
    | (`&` | `&&`) `mut` Expression

DereferenceExpression -> `*` Expression

AssignmentExpression -> Expression `=` Expression

CompoundAssignmentExpression ->
      Expression `+=` Expression
    | Expression `-=` Expression
    | Expression `*=` Expression
    | Expression `/=` Expression
    | Expression `%=` Expression
    | Expression `&=` Expression
    | Expression `|=` Expression
    | Expression `^=` Expression
    | Expression `<<=` Expression
    | Expression `>>=` Expression
```

`&place` 形成共享引用；`&mut place` 要求可变位置。应用于值表达式时，借用会具现化一个临时量。`*reference` 访问其目标，`*box` 在 [Box 规则](../14-heap/14.00-heap.md#box-access-and-moves)下访问其拥有的 `T`。其他类型（包括 `Vec`）不是解引用操作数。在前缀借用位置，`&&x` 表示 `&(&x)`；中缀 `left && right` 是短路布尔与。

每个显式的 `*` 执行一次解引用。解引用 `&T` 得到共享访问；解引用 `&mut T` 得到可变访问，除非是穿过共享引用到达的。存储在不可变局部变量、结构体、数组或 `Box` 中的 `&mut T` 仍可被解引用以修改其目标。一旦沿该位置的访问路径穿过共享引用，进一步的解引用就无法恢复可变访问。

下面所有参数都是不可变绑定。每个函数仍然可以通过其存储的可变引用来修改整数：

```rust,ignore
struct Holder<'a> {
    value: &'a mut i32,
}

fn through_local(value: &mut i32) {
    *value = 2; // one dereference reaches the integer
}

fn through_struct(holder: Holder<'_>) {
    *holder.value = 2; // modifies the integer, not the field holding the reference
}

fn through_array(values: [&mut i32; 1]) {
    *values[0] = 2; // indexes the reference, then dereferences it
}

fn through_box(value: Box<&mut i32>) {
    **value = 2; // first * accesses the Box content; second * follows &mut i32
}
```

以下函数无法编译，因为它们的第一次解引用穿过了共享引用，使内层可变引用无法授予可变访问：

```rust,ignore
fn through_shared_reference(value: &&mut i32) {
    **value = 2; // compile error: the outer & gives only shared access
}

fn through_shared_box(value: &Box<&mut i32>) {
    ***value = 2; // compile error: & then Box then &mut still crosses shared access
}
```

`place = value` 以所需的复制/移动行为进行存储。复合赋值对目标处的当前标量值应用相应的运算。两种形式都产生单元值。即使引用运算的降级最终使用相同的标量指令，下面的顺序规则仍然适用。

## 赋值目标

赋值目标是一个可变[位置](11.00-expressions.md#places-and-values)。被赋的值必须具有兼容的类型。不满足这些要求的目标属于编译错误。

诸如 `s = other;` 和 `a = other_array;` 的赋值在单个操作中将整个结构体或数组值赋给目标位置。

## 求值顺序

| 表达式形式 | 求值顺序 |
| --- | --- |
| 一元标量或共享引用运算 | 先对操作数求值，然后执行运算 |
| 普通二元算术、位运算、移位或比较，包括引用变体 | 先对左操作数求值，然后对右操作数求值，然后执行运算 |
| 惰性布尔 `&&` / <code>&#124;&#124;</code> | 对左侧 bool 求值；仅在需要时才对右侧求值 |
| 普通赋值 `place = value` | 先对右侧值求值，然后对目标地址求值，然后存储 |
| 右操作数为基本标量或共享引用的复合赋值 | 先对右操作数求值，然后对目标地址求值，然后执行标量读取/更新 |

所有受支持的复合赋值都使用相同的右侧优先顺序，无论右操作数是标量还是共享引用。每个操作数表达式和目标地址计算都只求值一次。目标的旧值在操作数求值之后读取。引用右操作数首先求值得到其引用值；其目标在执行标量运算时读取。借用有效性仍然由测试保证，而不是由必需的借用检查器检查。

<details>
<summary>复合赋值顺序示例</summary>

根据本课程规则：

```rust,ignore
fn destination(p: &mut i32) -> &mut i32 {
    println_i32(2);
    p
}

fn right_value() -> i32 {
    println_i32(1);
    3
}

fn right_reference(p: &i32) -> &i32 {
    println_i32(1);
    p
}

fn main() {
    let mut x = 0;
    let y = 3;
    *destination(&mut x) += right_value();       // prints 1, then 2
    *destination(&mut x) += right_reference(&y); // prints 1, then 2
}
```

官方测试与复合赋值两个操作数的相对求值顺序无关。上面的示例说明了规定的行为，但评分测试套件不检查操作数之间的求值顺序。

</details>

覆盖或丢弃现有值不会清除或清零其在内存中的字节。替换容器不需要递归析构或立即释放；其旧的堆存储可以依据[堆清理规则](../14-heap/14.00-heap.md#heap-cleanup)保留。
