# use 声明

```grammar,items
UseDeclaration -> `use` UseTree `;`

UseTree ->
      (UsePath? `::`)? (`*` | `{` (UseTree (`,` UseTree)* `,`?)? `}`)
    | UsePath (`as` (IDENTIFIER | `_`))?

UsePath -> `::`? UsePathSegment (`::` UsePathSegment)*

UsePathSegment -> IDENTIFIER | `self` | `super` | `crate`
```

use 声明被接受为顶层项，以便同一份测试源代码可以用 Rust 和课程支持 crate 编译。例如：

```rust,ignore
use rx::core::*;

fn main() {
    println_i32(42);
}
```

该语法接受单个路径、`*` 通配、带可选尾随逗号的嵌套花括号组以及 `as` 别名。例如，`use rx::core::println_i32;` 和 `use rx::core::{get_i32, println_i32};` 也是被接受的。use 声明不能出现在表达式块或 `impl` 块中，也不接受可见性修饰符或属性。

解析之后，编译器可以丢弃整个声明。编译器不解析导入路径，不加载 crate 或模块，不向任何作用域引入名称或别名，不检查导入冲突，也不为该声明生成 LLVM IR。诸如 `println_i32` 这样的内建项在 Rx 中已经可用，无论是否有 `use` 声明。

[use 兼容性保证](../01-undefined-behavior/01.00-undefined-behavior.md#use-compatibility)确保测试不依赖额外的导入语义。use 声明中接受的扩展路径语法（包括多段路径、前导 `::`、`crate` 和 `super`）不适用于[类型和表达式路径](../06-names/06.01-paths.md)。另见[解析后可能被丢弃的语法](../04-grammar/04.00-grammar.md#syntax-that-may-be-discarded-after-parsing)。
